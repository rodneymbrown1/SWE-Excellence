# Tick wrap {.chapter data-part="PART B · RTOS LABS" data-label="Lab R7"}

<p class="lede"><b>Goal.</b> Make a 16-bit tick wrap in a second instead of a minute, and see code that works until it doesn't. <b>Book.</b> Chapter 3. <b>File.</b> <code>labs/rtos/r7_tickwrap/main.c</code>.</p>

The build uses a 16-bit tick (wraps every 65.536 s at 1 kHz). The program fast-forwards the tick count to 65,500 with `xTaskCatchUpTicks` (which must **not** be called with the scheduler suspended), then: (1) a kernel periodic delay across the wrap, (2) a hand-written 100-tick timeout started 30 ticks before the wrap, in two forms.

**Predict first.** (a) Do the kernel's own periodic wake-ups survive the wrap? (b) How many loop iterations does the naive timeout run? The safe one?

```
make -C labs/rtos/r7_tickwrap && python3 labs/rtos/run.py labs/rtos/r7_tickwrap/build/r7_tickwrap.elf
```
