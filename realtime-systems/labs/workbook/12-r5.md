# Three watchdogs, one fault {.chapter data-part="PART B · RTOS LABS" data-label="Lab R5"}

<p class="lede"><b>Goal.</b> Run three ways of feeding a watchdog against the same injected fault and see which one notices. <b>Book.</b> Chapter 19. <b>File.</b> <code>labs/rtos/r5_watchdog/main.c</code>.</p>

Three tasks (`sensor` 10 ms, `control` 20 ms, `logger` 100 ms). After 15 cycles `control` blocks forever on a lock a ghost task holds. A software watchdog (emulated with a timer interrupt; timeout 400 ms) resets the CPU with a real reset request if not fed.

- **MODE 1:** the timer interrupt feeds it.
- **MODE 2:** the lowest-priority task feeds it.
- **MODE 3:** a supervisor feeds it only if every task has checked in since the last feed.

**Predict first.** For each mode: does a reset happen within 1.5 s? What does the system know afterwards?

```
for m in 1 2 3; do make -C labs/rtos/r5_watchdog clean; make -C labs/rtos/r5_watchdog MODE=$m
  python3 labs/rtos/run.py labs/rtos/r5_watchdog/build/r5_watchdog.elf --reboot; done
```
