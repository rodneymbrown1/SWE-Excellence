# Predict, then measure a task set {.chapter data-part="PART B · RTOS LABS" data-label="Lab R2"}

<p class="lede"><b>Goal.</b> Compute worst-case response times with the analysis, then measure them on a real kernel and explain every difference. <b>Book.</b> Chapters 8 and 9. <b>File.</b> <code>labs/rtos/r2_rm/main.c</code>.</p>

Periodic tasks, rate-monotonic priorities. Set A: C = 1, 2, 3 ms, T = 4, 6, 12 ms (U = 0.833). Set B: C = 2, 4 ms, T = 5, 7 ms (U = 0.971). Each job's response is measured from the hardware time of the tick it was released on to its completion; job 0 is excluded (it includes task creation).

**Predict first.** (a) With `rtcalc.py a:1:4 b:2:6 c:3:12`, the three worst-case responses. (b) Set B: which task can miss and by how much? (c) What fraction of that task's jobs do you expect to miss, from the simulator: `python3 -c "from rtsim import *; …"` or `rtcalc` (hint: one in five). (d) Will the real kernel agree?
