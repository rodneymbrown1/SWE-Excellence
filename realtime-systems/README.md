# ON TIME — real-time fundamentals for software engineers

A course, a field handbook and a lab workbook for an engineer who writes **application and middleware code on top of an RTOS framework** and wants the fundamentals that framework silently assumes: timing, scheduling, messaging, synchronization, reliability, observability. Companion to `../debugging/` (*State First*).

**Print these three files** (US Letter, Atkinson Hyperlegible, tagged PDF with outline, grayscale-safe):

| File | What | Pages |
|---|---|---|
| `print/on-time-book.pdf` | **ON TIME**: 24 chapters in 6 parts + 6 appendices. History-ordered: loop → timer → interrupt → cyclic executive → tasks → priorities → analysis → locks → memory → queues → pub/sub → lifecycles → watchdogs → tracing → distributed → frameworks → implicit requirements → a worked system | ~116 |
| `print/on-time-handbook.pdf` | **Field Handbook**: first hour on a device, inventory forms, Component Card, timing budget sheet, build checklist, debug triage, review checklist, measuring recipes, the 45 implicit requirements, incident patterns | ~34 |
| `print/on-time-labs.pdf` | **Lab Workbook**: 16 labs + setup, predictions first, real captured output, answer key | ~60 |

Rebuild: `python3 print/build.py [book|handbook|labs|all]` (needs pandoc, Google Chrome, poppler, Pillow). A layout-fit step adjusts each chapter's scale by a few percent so no chapter ends on a near-empty page; `python3 print/qa.py print/on-time-book.pdf` reports page fill.

## Folders

| Folder | Contents |
|---|---|
| `book/chapters/`, `handbook/chapters/`, `labs/workbook/` | Markdown sources of the three PDFs |
| `book/diagrams/` | 35 SVG figures, generated by `book/diagrams/gen/make_figures.py` — several are drawn from real simulator output and real QEMU traces |
| `labs/host/` | Labs H1–H5: C and Python, no dependencies; `rtsim.py` is an exact scheduler workbench, `rtcalc.py` a schedulability calculator |
| `labs/rtos/` | Labs R0–R10: FreeRTOS V11.3.2 on QEMU `mps2-an385` (Cortex-M3), freestanding BSP, deterministic clock; `gdb/` has a FreeRTOS-aware gdb helper |
| `labs/tools/` | `trace2gantt.py`, `lathist.py` |
| `labs/transcripts/` | every output printed in the workbook and book (regenerate with `labs/host_capture.sh`, `labs/rtos/capture.sh`, `labs/rtos/gdb/run_session.sh`) |
| `research/` | the evidence: source registry, topical notes, case files, **what could not be verified**, lab environment notes. `_raw/` holds downloaded sources (git-ignored) |
| `print/` | build pipeline, stylesheet, fonts |

## Quick start

```
sh labs/fetch-deps.sh                          # fetch FreeRTOS-Kernel V11.3.2, check tools
make -C labs/host test                         # host labs
make -C labs/rtos/r0_hello && python3 labs/rtos/run.py labs/rtos/r0_hello/build/r0_hello.elf
python3 labs/host/rtcalc.py a:1:4 b:2:6 c:3:12  # schedulability of your own task set
```

## Honesty notes

- Items marked **[RAN]** were executed on the project machine; **[MANUAL]** (e.g. VS Code configuration) were not. **[SEC]** marks expert testimony or press reports (notably the Toyota material, which is a plaintiff's expert and disputed).
- RTOS-lab times are *virtual* microseconds from an emulator; they teach relationships (model vs measurement), not any board's speed.
- Read `research/09-claims-we-could-not-verify.md` before quoting anything from these documents.
